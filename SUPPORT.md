# Getting help

Start with [setup](docs/setup.md), [troubleshooting](docs/troubleshooting.md), and the
[operation reference](docs/reference.md). This project is an alpha; check the
[verification record](VERIFICATION.md) before assuming a client or live behavior is supported.

- **Reproducible bug:** use the bug report form and include version, OS, installation
  method, a minimal synthetic example, and the safe error code.
- **Feature proposal:** describe the user task, current limitation, and a small complete
  change using the feature request form. Discuss substantial additions before coding.
- **Usage question:** use the question form. Share commands with synthetic data, not
  account configuration, real email/calendar content, or credentials.
- **Homebrew packaging:** report formula/build problems in
  [homebrew-tap](https://github.com/MarkUnthank/homebrew-tap/issues).
- **Vulnerability:** use [private security reporting](SECURITY.md).
- **Conduct:** see [community conduct](CODE_OF_CONDUCT.md).

Support and reviews are best effort. There is no guaranteed response time or paid
support service. Never send a password to a maintainer or an agent to diagnose a problem.
